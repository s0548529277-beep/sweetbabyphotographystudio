- **2026-11-02 (09:20 Israel) — Claude (chat, via GitHub, owner request "show the answer as it is being written — do it now"):** site chat now STREAMS the reply. New `POST /api/chat-stream` (`src/routes/api.chat-stream.ts` → `src/lib/chat-stream.server.ts`): runs the same turn as `chatWithBot` with `streamText` on one direct Gemini key (`pickStreamingGeminiModel()` in `ai-gateway.server.ts`, random key, same model + `thinkingLevel: "low"`) and sends newline-JSON events (`s` open, `d` text, `r` clear, `f` final `{reply,ui,isAdmin}`, `x` failed). If the stream fails before it produced an answer, the server falls back to `generateTextResilient` (all keys, then Lovable) and sends the answer in one piece. To keep one source of truth, `chatWithBot` was split into `prepareChatTurn` (auth, knowledge, admin check, prompt, tools) and `finishChatTurn` (cards, chat log, important-chat notification) in `ai.functions.ts` — both the server function and the stream use them. Client: `src/lib/chat-stream-reader.ts` + `ChatBot.tsx` `send()` (text appears word by word, the "נועה כותבת…" placeholder hides at the first word; if the stream cannot be opened it uses the old `chatWithBot`; if it breaks AFTER starting it shows the busy message and does NOT re-run the turn, so a booking is never created twice). Do not name this helper `*.client.ts` — Start treats that suffix as client-only and the SSR build fails. `routeTree.gen.ts` regenerated by the build. tsc + vite build OK; stream reader tested with fake streams; NOT tested against live Gemini (no keys in the sandbox) — try one real chat after deploy, including a question that needs a tool (e.g. availability).
